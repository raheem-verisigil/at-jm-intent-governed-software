Intent-governed software change

Make software changes answer to the intent behind them.

AT-JM is building a runtime layer that helps teams express what a change must preserve, evaluate requests against explicit boundaries, and review evidence before release.

Try the policy evaluatorSee how it works

Prototype v0.1: the demo validates contract structure and evaluates policy inputs. It does not run code, control production systems, or replace an organization's authorization process.

Designed for engineering teams

Keep intent visible through the change process.

Turn critical requirements and boundaries into explicit inputs teams can review, test and revisit.

01 / DEFINE

Intent contracts

Describe the goal, acceptance criteria, invariants, prohibitions and approval conditions for a proposed change.

02 / EVALUATE

Policy decisions

Evaluate structured requests with deterministic rules and return allow, deny, approval-required or indeterminate outcomes.

03 / REVIEW

Evidence-aware release

Make missing, failed or conflicting evidence visible rather than treating uncertainty as permission.

Workflow

From change request to an inspectable decision.

AT-JM's product direction connects approved intent, explicit authority boundaries, independent verification and human release decisions.

01 Define outcome and constraints

02 Evaluate the requested action and evidence

03 Route sensitive actions for human review

04 Verify results before a release decision

The current prototype implements contract-shape validation and bounded policy evaluation only. The broader workflow describes product direction, not deployed functionality.
